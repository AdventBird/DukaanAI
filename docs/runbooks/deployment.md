# Deployment runbook

Deploy `apps/web` as a static PWA with SPA route fallback and HTTPS; deploy `apps/api` as a Node service; use persistent managed PostgreSQL (including Supabase PostgreSQL). Configure `DATABASE_URL`, `WEB_ORIGIN`, `PORT`, `SUPABASE_URL`, and `SUPABASE_ANON_KEY` through the deployment secret store. Do not deploy with `AUTH_MODE=demo`. API clients must provide a verified Supabase bearer token and each identity must have exactly one `User.authSubject` membership. The web app currently lacks a login screen, so production authentication must be supplied by the hosting/client integration before exposing protected views. `/api/health` is a liveness endpoint; database readiness is not yet wired. AI actions are explicitly disabled during data-readiness work. Review and back up before applying the pending supplier/procurement/auth migration; do not run it automatically against a live database.
